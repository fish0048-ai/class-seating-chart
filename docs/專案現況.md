上課模式：

- 選班級（801、802、803、804、範例班）
- 上課主畫面預設**依座號**排列（不再用傳統座位表）；可切換成**依分組**顯示
- 加分＝自選固定分（1／2／5）＋命運隨機（+0／+1／+2，約 1% 為 -1）；點學生後先出命運畫面，揭曉／寫入時**只顯示合計**，不顯示固定分或命運分拆開
- 扣分仍用 1／2／5；互教模式：先點教的人、再點被教的人；被教者拿主分、教的人拿 +1 獎勵（不套用整組加扣）
- 排行只鼓勵為主：顯示今日分數與名次（不顯示累積總分）
- 抽籤抽出後命運加分：+0／+1／+2（約 1% 為 -1），可套用或略過
- 作答定時器：可選 30 秒～10 分或自訂分秒；開始／暫停／重設；時間到會提示並響一聲；設定會記住

- 小組分會加進每位組員的平時加扣
- 小組扣分時請先點那位同學再扣整組，成績統計才會記下「因誰」
- **缺交作業**：教師模式可登錄各班缺交名單；已建立的項目可直接點座號增減；上課模式該班會顯示缺交座號，座位卡也會標「缺交」

實驗室模式：

- 固定 6 組，座位分六個區塊
- 可依座號或隨機分成六組；拖到別區換組
- 加扣預設套用整組（與上課分組是兩套資料，互不覆蓋）

教師模式分頁：名單、課表、**成績**（每日加扣／學期成績／圖表分析）、教學日誌、缺交作業、設定與上傳。

## 4. 資料怎麼存

主資料是一整份 JSON store，寫在成績庫工作表「雲端資料」（分段，每段約 45000 字）。老師要看分數請打開同一份試算表的 **「成績」**、**「每日加扣」**（不要改「雲端資料」）。這幾張可讀表（含「學生」「班級設定」）**存檔約 1 分鐘後**由時間觸發器 `refreshReadableSheets` 一次寫出，連續存檔只寫一次；急著看可用試算表選單「座位表 → 立即更新成績／學生工作表」。觸發器沒授權時會退回存檔當下就寫。

後端快取（CacheService）：雲端更新時間（`getStoreMeta` 不必開試算表）、課表 10 分鐘（按「重新整理課表」會帶 `fresh` 重讀）、Google 登入驗證到憑證到期為止。`ensureSheets_` 只在 `SHEETS_SCHEMA_VERSION` 變了才重跑。`getStore` 讀取也會拿鎖，避免讀到寫一半的分段。

結構大意：

```
store.classes[班名] = {
  className, rows, cols, version, updatedAt,
  students: [{ seatNo, name, score, row, col, note }],
  groups: { size, assign: { 座號: 組號 }, scores: { 組號: 分 } },
  lab:    { assign: { 座號: 1~6 }, scores: { "1"~"6": 分 } }
}
store.history[]   操作紀錄（含 groupId、seatNos、causeSeatNo、causeName、lab）
store.daily{}     每天加扣結算
store.grades{}    成績簿
store.mockExam    舊的學力診斷能力等級（模擬考分頁已下架，只保留資料；不要把原始 Excel 推進 git）
store.lessonLog   教學日誌（各班目前進度 + 日期紀錄）
store.scheduleChanges[]  調課提醒（週次／班級／原節→新節；只影響網站課表顯示）
store.hwMissing{班:[]}  缺交作業名單（作業名稱＋座號；上課模式顯示）
store.scoreDate   目前加扣所屬日期
store.updatedAt
```

`api.js` 的 `normalize()` **必須保留 `groups` 與 `lab`**，否則存檔會丟掉分組。

存檔：座位、分組改完約 400ms 會推雲端。**加扣、復原、重製加扣不會一改就上傳**，先留在這台，換機或下課前請按「立即同步」。還沒同步的加扣存在 `localStorage`（`class-seating-score-hold`），關掉分頁或瀏覽器也不會消失；有未同步資料時離開頁面會跳出瀏覽器提醒。重新開啟時若雲端已被別台更新，會把這台還沒上傳的加扣紀錄（依 `history` 比對）**重播合併**到雲端新資料上並提示老師按「立即同步」，不會整包丟掉。讀取：`getStore` 用 POST，並帶 Google `idToken`。

背景同步（約每 25 秒）：先呼叫輕量的 `getStoreMeta`，只取「雲端資料」表 C2 的更新時間；時間沒變就不下載整包，有變才 `getStore`。分頁在背景時不輪詢；上一次還沒回來不會再送；失敗時間隔加倍（最多 2 分鐘），成功後恢復 25 秒。後端還沒部署 `getStoreMeta`（回「未知的操作」）時，前端自動退回整包比對。`getStore` 只在班級有學生、分組空白且沒有 `clearedAt` 時才讀「學生」表補分組。Apps Script 每次請求本身約 5–13 秒，這是平台延遲，前端無法消除。

成績同步防護（避免空白蓋掉舊資料）：

- Excel「成績輸入」匯入時，**空白格不改動**，只寫有填的分數／請假；說明工作表也有寫
- 學校讀卡成績（例如 `SCORE.XLS`，欄位含「班級名稱、座號、成績」）也用「從 Excel 匯入」：自動辨識格式，一次匯入多班；班級代碼 01→801（只有唯一一班尾碼相符才對應）；欄名取「試卷分類」的「第N次學科競試」，放在**段考**，各班共用同一欄（同名欄已存在就沿用、只覆蓋檔案裡的座號）。寫入前會跳確認，列出各班人數、對不到的班級、名單沒有的座號、姓名不同的座號。原始 XLS 有學生姓名，不要 commit
- 網頁成績表：**只儲存你有改過的格子**；沒動過的空白不會把雲端舊分清掉。要清除某格請手動清空該格（會記成有改過）
- 成績簿尚未從雲端載入完成前，不允許自動存／匯入／新增欄；重新載入時會取消尚未寫入的自動存
- 前端 `pushCloud_` 與後端 `putCloudStore` 上傳前會保護：缺班級、空成績簿、空每日加扣、同日加扣被整班歸零、**意外**空分組／實驗室分組、教學日誌缺班／缺紀錄時，保留並合併雲端舊資料
- 教學日誌按儲存後會**立刻推雲端**；若與另一台衝突會先合併兩邊日誌再上傳，不會用空白整包蓋掉
- 「立即同步」若本機分組是空的，**預設**不會用空分組蓋掉雲端；但老師按「清除分組」會帶 `clearedAt` 標記，同步時會把空白分組寫上雲端（也不會再被學生表／操作紀錄自動拼回）
- 座號 `01`／`1` 會對齊，避免分組被 normalize 清掉
- 分組不見時（非刻意清除）：設定頁按「嘗試還原分組」，或 Apps Script 執行 `repairGroupsFromStudentSheet`
- 儲存成績簿時，若某欄分數異常大量消失，會補回雲端舊分；空陣列不會整類清掉
- **改 `Code.gs` 後務必貼上 Apps Script 並更新同一支部署**，後端防護才會生效

## 6. 改程式時絕對不要做的事

1. **不要在 `renderLabBoard`／每次重繪時呼叫存檔**（以前會無限 `saveLab`，全班卡在「正在載入」）。進入實驗室只在第一次缺分組時 `persistLab` 一次。
2. **`highlightDropTarget` 等函式不要多一個 `}`**。`app.js` 括號一錯，整份 JS 不跑，畫面永遠「正在載入」、沒有班級。改完請在瀏覽器確認有座位卡。`styles.css` 也一樣：多一個 `}` 會讓 `@media` 提早結束，平板規則套到電腦（曾讓實驗室變 2×3）。
3. **課表試算表只讀**，不要寫入成績、名單、加扣。課表相關功能（即時讀取、教學日誌的考試／實驗、調課提醒、國定假日）都只改網站顯示，資料存在成績庫雲端 JSON。
4. **抽籤加權不要寫進畫面、README、或跟老師說明的文字。**
5. **學生真實名單不要 commit 進公開 git**（不要把填好的 CSV／個資推進 GitHub）。
6. 不要改 git config、不要 `--force` push。
7. 不要把 `.env`、憑證當一般檔案 commit。OAuth 用戶端 ID 本來就在前端公開，可以留在 `config.js`。
8. 非教師帳號即使改了前端，也不該能讀到或寫入任何資料（後端每個動作都檢查教師）。
9. `saveStore` 對非教師帳號直接 return，不要把本機亂改推上雲端。
10. **不要把作業檢核資料寫進 `getStore`／`putStore` 那包 JSON**。作業用獨立工作表 `HW_*`，以免座位表變慢或卡死。
11. 第一版**不要呼叫 Classroom API**。`CLASSROOM_API_ENABLED` 必須是 `false`。學生頁不可要求 Classroom roster／CourseWork 授權。
