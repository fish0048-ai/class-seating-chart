## 1. 老師現在可以做什麼

必須先用 **Google 帳號**登入。

| 角色 | 帳號 | 能做的事 |
| --- | --- | --- |
| 教師 | 目前只有 `chunhsinkuo@kcis.hc.edu.tw` | 加扣分、拖座位、抽籤、分組、實驗室、教師模式（名單／課表／成績／統計／模擬考／教學日誌／作業檢核／設定） |

上課模式：

- 選班級（801、802、803、804、範例班）
- 上課主畫面預設**依座號**排列（不再用傳統座位表）；可切換成**依分組**顯示
- 加分＝自選固定分（1／2／5）＋命運隨機（+0／+1／+2，約 1% 為 -1）；點學生後先出命運畫面，揭曉／寫入時**只顯示合計**，不顯示固定分或命運分拆開
- 扣分仍用 1／2／5；互教模式：先點教的人、再點被教的人；被教者拿主分、教的人拿 +1 獎勵（不套用整組加扣）
- 排行只鼓勵為主：顯示今日分數與名次（不顯示累積總分）
- 抽籤抽出後命運加分：+0／+1／+2（約 1% 為 -1），可套用或略過
- 作答定時器：可選 30 秒～10 分或自訂分秒；開始／暫停／重設；時間到會提示並響一聲；設定會記住
- 分組：每組人數、隨機／手動；可依目前分組把同一組排坐在一起（組的位置會打散）
- 小組分會加進每位組員的平時加扣
- 小組扣分時請先點那位同學再扣整組，成績統計才會記下「因誰」

實驗室模式：

- 固定 6 組，座位分六個區塊
- 可依座號或隨機分成六組；拖到別區換組
- 加扣預設套用整組（與上課分組是兩套資料，互不覆蓋）

教師模式分頁：名單、課表、成績表、成績統計表（含小組扣分因誰）、統計圖表（班級／全校／個人）、模擬考、教學日誌、作業檢核、設定與上傳。

統計圖表：

- **班級分析**：上課加扣、平時考試（黃卷／早自習）、段考分開統計；另有實作／作業與進階圖。上面可切類型
- **全校統計**：各班比較時，上課加扣、平時考試、段考也分開看；也可看全校前 10 名與需要關心的學生。在任一班「新增成績欄」會同步到所有班級（同一欄編號），全校統計可依同一欄比較各班平均
- **個人分析**：單一學生與全班比較
- **模擬考標註**：可匯入學力診斷「學校能力等級成績統計表」；只在教師模式「模擬考」分頁顯示國英數社自、寫作、五科標示與校排，上課／實驗室座位卡不標
- **教學日誌**：各班一張進度卡，記錄目前上到哪；可依日期留下本堂備註，平板與筆電共用，不寫進課表試算表
- **成績欄**：新增／刪除會套用到全校各班（不含範例班）；各班分數仍分開登錄

晚上 10 點會自動把當天加扣分存進日期紀錄，分數歸零開始下一天。

## 4. 資料怎麼存

主資料是一整份 JSON store，寫在成績庫工作表「雲端資料」（分段，每段約 45000 字）。老師要看分數請打開同一份試算表的 **「成績」**、**「每日加扣」**（網頁存檔時會自動寫出，不要改「雲端資料」）。

結構大意：

```
store.classes[班名] = {
  className, rows, cols, version, updatedAt,
  students: [{ seatNo, name, score, row, col, note }],
  groups: { size, assign: { 座號: 組號 }, scores: { 組號: 分 } },
  lab:    { assign: { 座號: 1~6 }, scores: { "1"~"6": 分 } }
}
store.history[]   操作紀錄（含 groupId、seatNos、causeSeatNo、causeName、lab）
store.daily{}     每天加扣結算
store.grades{}    成績簿
store.mockExam    學力診斷能力等級（只在教師模式「模擬考」看；不要把原始 Excel 推進 git）
store.lessonLog   教學日誌（各班目前進度 + 日期紀錄）
store.scoreDate   目前加扣所屬日期
store.updatedAt
```

`api.js` 的 `normalize()` **必須保留 `groups` 與 `lab`**，否則存檔會丟掉分組。

存檔：座位、分組改完約 400ms 會推雲端。**加扣、復原、重製加扣不會一改就上傳**，先留在這台，換機或下課前請按「立即同步」。背景分頁不會把舊資料蓋上雲端；若另一台已經存過較新的，這台會拒絕覆蓋並請你重新載入。讀取：`getStore` 用 POST，並帶 Google `idToken`。

成績同步防護（避免空白蓋掉舊資料）：

- Excel「成績輸入」匯入時，**空白格不改動**，只寫有填的分數／請假；說明工作表也有寫
- 網頁成績表：**只儲存你有改過的格子**；沒動過的空白不會把雲端舊分清掉。要清除某格請手動清空該格（會記成有改過）
- 成績簿尚未從雲端載入完成前，不允許自動存／匯入／新增欄；重新載入時會取消尚未寫入的自動存
- 前端 `pushCloud_` 與後端 `putCloudStore` 上傳前會保護：缺班級、空成績簿、空每日加扣、同日加扣被整班歸零、**意外**空分組／實驗室分組、教學日誌缺班／缺紀錄時，保留並合併雲端舊資料
- 教學日誌按儲存後會**立刻推雲端**；若與另一台衝突會先合併兩邊日誌再上傳，不會用空白整包蓋掉
- 「立即同步」若本機分組是空的，**預設**不會用空分組蓋掉雲端；但老師按「清除分組」會帶 `clearedAt` 標記，同步時會把空白分組寫上雲端（也不會再被學生表／操作紀錄自動拼回）
- 座號 `01`／`1` 會對齊，避免分組被 normalize 清掉
- 分組不見時（非刻意清除）：設定頁按「嘗試還原分組」，或 Apps Script 執行 `repairGroupsFromStudentSheet`
- 儲存成績簿時，若某欄分數異常大量消失，會補回雲端舊分；空陣列不會整類清掉
- **改 `Code.gs` 後務必貼上 Apps Script 並更新同一支部署**，後端防護才會生效

## 9. 紙本作業檢核（低權限 A，不依賴 Classroom API）

這是座位表之外的獨立模組，資料存在成績庫的 `HW_*` 工作表，**不寫進雲端 JSON**。

學生連結（同一支 `/exec`）：

`{WEB_APP_URL}?assignment=HW005`

教師在教師模式 → **作業檢核** 建立作業、複製連結，貼到 Google Classroom 當入口。Classroom 不讀 roster，也不回寫成績。`CLASSROOM_API_ENABLED = false`。`Code.gs` 內有 `ClassroomSyncService` 空殼（`syncGrade`／`syncRoster`／`createCourseWork`），第一版不會打 API。

### 工作表

| 表 | 用途 |
| --- | --- |
| `HW_Students` | 班級、座號、姓名、Email（不要只寫在「學生」表，那個表會被座位同步整表重寫） |
| `HW_Assignments` | 作業設定與學生連結 |
| `HW_Submissions` | 提交、遲交工作天、分數、教師加減、允許補交 |
| `HW_WrongItems` | 錯題與原因 |
| `HW_SpotChecks` | 抽到的題號 |
| `HW_Overrides` | 個別延長截止 |
| `HW_Questions` | 題號與詳解（第一版詳解留空，學生對照紙本） |

預設：滿分 100、每工作天扣 10、最低 0、抽查 2 題。編號自動 `HW001`、`HW002`…  
遲交只算週一到週五。準時 100、遲 1 個工作天 90。截止後未交顯示「未交」，**不自動 0 分**。

### 學生身分

部署是「執行身分＝我、對象＝任何人」，`Session.getActiveUser()` 多半是空的。辨識順序：Google 信箱（只要 email，不要 Classroom 授權）→ 否則班級＋座號＋姓名必須與 `HW_Students` 三欄一致。之後用 HMAC session（約 8 小時），後端不信 URL／前端傳來的座號。

### 老師部署（作業檢核一定要做）

1. 把最新 `Code.gs` **全部貼上**並儲存
2. 在編輯器上方選函式 `authorizeScript`，按**執行**，允許「連線至外部服務」（驗證 Google 登入需要這個）
3. 在 Apps Script 新增檔案 `HwStudent.html`，把倉庫根目錄的 `HwStudent.html` **全部貼上**
4. **部署 → 管理部署 → 編輯**現有網頁應用程式，版本選「新版本」（`/exec` 不要換）。若第一次還沒有部署，才用「新增部署作業」，執行身分「我」、對象「任何人」，並把新網址貼進 `docs/config.js` 的 `apiUrl`
5. 教師模式 → 作業檢核 → 從座位表匯入本班名單；Email 請在試算表 `HW_Students` 補上（匯出 Classroom CSV 才有信箱）

### 作業檢核驗收

1. 學生用 `?assignment=HW00x` 打開 Apps Script 網頁，不是 GitHub Pages。
2. 能勾錯題 1…N。
3. 每題能選原因（計算錯誤／觀念不清／看錯題／粗心／其他）。
4. 須確認已紅筆訂正才能提交。
5. 身分由後端 session 驗證，不能在網址指定別人座號來看成績。
6. 提交後只顯示自己的作業名、時間、狀態、分數、扣分；有教師調整才顯示加減與原因。
7. 抽查只顯示題號「請對照紙本講義第 X 題」，沒有詳解內文。
8. 遲交依工作天扣分；週六日不增加天數。未交不自動 0，教師可給 0 或允許補交。
9. 學生流程完全不要求 Classroom API 授權。
10. 改完後端必須新增部署，並更新 `HwStudent.html`。
11. `CLASSROOM_API_ENABLED = false` 時，建立作業、學生繳交、教師看表／複製連結／CSV／調分仍可用。
